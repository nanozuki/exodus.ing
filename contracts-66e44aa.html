use-cases

Implement server business operations that require external capabilities.4 变更7 声明

Implement server business operations that require external capabilities. Callers supply capabilities in deps and invocation data in params; use cases import repository functions and pass deps.db. Repositories own transactions and persistence consistency. Request boundaries own request context, cookies, redirects, and remote-query refreshes. Use cases neither import the service registry nor read environment variables.

Deterministic Markdown compilation and business calculations stay in their owning operations; only actual shared business scenarios receive separate exported functions.

AppDatabase comes from src/lib/server/db/schema.ts; business data comes from src/lib/models. Callers supply trusted authenticated actors, provider identities, parsed URLs, and request-independent input values. Repository/adapter failures propagate; expected business failures use tagged application errors, with field keys for correctable input failures. Each use case declares only the dependencies it uses. Request entry points supply now from adapters/clock.ts; use cases never obtain the current time directly.
