# Project Instructions

Before designing a feature, deciding where code belongs, or changing or
reviewing application code, read
[Architecture and Development Conventions](docs/architecture.md).

Before writing, editing, or reviewing code, read
[Code Style](docs/code-style.md).

## Ownership and Git workflow

The user owns and is responsible for the code. Use the user's configured Git
identity and name branches after the work, such as `ci/parallel-checks`. Keep
branch names, commit messages (including trailers), and pull request titles,
descriptions, and comments free of agent, model, or AI tool names and
attribution. Describe the change itself; omit generated-by notices and agent
co-author trailers.

Create pull requests in the ready-for-review state.
